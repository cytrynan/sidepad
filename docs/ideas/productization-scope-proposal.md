# sidepad プロダクト化スコープ提案（v1 / v1.5 / やらない）

## 現在地（2026-08-08）

技術検証はすべて完了し、エンドツーエンドが閉じている:
仮想DP 2048x1536@120（VDD）→ DXGIキャプチャ → AMF H.264 40Mbps CBR → usbmux直結USB → VideoToolboxデコード → Metal 120Hz表示。
実測: 2391/2391欠落0・エンコードfps≈120・latency p99 6.3ms・遅延予算20〜35ms内。

ただし**全段がspikeの手動起動**: `pc_encode_spike` をCLIで叩き、表示番号を毎回 `--list-displays` で確認し、iPadアプリも手動起動。日常の道具にはまだなっていない。

## v1 の完了条件（提案）

> **「USB-Cケーブルを挿すと10秒以内に拡張ディスプレイとして使え、抜くと仮想DPが消えて元のモニタ構成に戻る。半日連用して破綻しない」**

証明可能な形:
1. 接続→表示可能までの所要時間を計測（目標10秒以内）
2. ケーブル抜き差し20回連続で自動復帰成功
3. 4時間連続稼働で fps・メモリ使用量が横ばい（ログで確認）

## スコープ

### v1: 常駐運用（必須・これだけで「使える道具」になる）

1. **PC側常駐化（sidepadd）**: iPad接続検知（usbmuxデバイスイベント）→ 仮想DP有効化（devcon enable）→ 仮想DPの表示番号自動特定（既存 `--list-displays` 判定を流用）→ キャプチャ/エンコード/送信開始。切断で逆順に畳む。形態は**ログオン時自動起動のコンソール常駐**（タスクスケジューラ）。トレイアプリ化は後回し（見た目より先に動作）
2. **仮想DPのオンオフ自動化**: 使わない間は仮想DPを無効化しモニタ構成を汚さない（devcon enable/disable を常駐から制御。--display番号ずれ問題もこれで吸収）
3. **iPad側の運用整備**: 接続待ち受け画面・切断時の自動再接続・統計オーバーレイのトグル（例: 3本指タップ）
4. **耐障害**: PCスリープ/復帰・ケーブル抜き差し・エンコーダ再初期化（iPad側のVTセッション再生成＋バックオフは実装済み）

概算: 3〜4作業セッション。iPad側変更は再インストールを伴うため、iPad側タスクは1回にまとめて実施。

### v1.5: 入力と画質（v1が回ってから）

5. **タッチ→PC返送**: タップ=クリック・ドラッグ=カーソル移動・2本指スクロール。既存TCP接続の逆方向メッセージ＋Windows側 SendInput（仮想DP座標へマップ）。Apple Pencilは筆圧なしのポインタ扱いまで
6. **設定はconfigファイルのみ**: ビットレート・fps上限・解像度プリセット。GUIは作らない（自分用）
7. **HiDPI/ネイティブ解像度の実測1回**: 現行2048x1536＋Windowsスケーリング200%を標準としつつ、iPadネイティブ2732x2048@120を1回だけ実測。p99遅延が予算内なら採用、超えるなら現行維持で確定

概算: 2〜3作業セッション。

### 運用（コード外・v1と並行可）

8. **7日再署名の自動化**: **AltServer常駐を導入して検証**（Wi-Fi自動リフレッシュ）。AltServerはAMDS前提なので運用経路（usbmux直結）と両立し、開発インストール用の `usbipd bind` 切替摩擦を避けられる。不成立なら週次リマインド＋ `install-to-ipad.ps1` にフォールバック。K作業はAltServerへのApple IDログインのみ
9. 積み残しの回収: GitHub issue起票（`gh auth login` がK作業として未実施）

### やらない（v2以降 or 見送り）

- **Wi-Fiモード** — ジッタが目的（低遅延）に反する。有線で完結している
- **クリップボード共有** — 便利だが学習要素が薄く、優先度低
- **Apple Pencilの筆圧・傾き** — Windows Ink連携まで作ると重い。ポインタ扱いで十分
- **配布対応**（署名・公証・他環境GPU対応）— 自分用＋学習の目的を維持。配布に舵を切るなら別途スコープを起こす
- **音声転送** — PC本体スピーカーで足りる

## Kに判断してほしい点（推奨込み）

1. **タッチ返送をv1.5に入れるか** → 推奨: 入れる。拡張ディスプレイの操作性が段違いに上がり、実装は既存経路の逆方向利用で小さい
2. **ネイティブ2732x2048化** → 推奨: v1.5で実測1回だけ。予算内なら採用、ダメなら深追いしない
3. **再署名の方式** → 推奨: AltServer常駐（理由は上記8）
4. **着手順** → 推奨: v1の 1→2→4 をPC側でまとめて進め、3（iPad側）は最後に1回で実施。並行して8のAltServer検証
