# 要求内容（タッチ→PC返送・v1.5先頭タスク）

## 概要

iPad画面へのタッチをPCのマウス入力として返送する（K指示 2026-08-11「タップ反応するようにするのを先に実装したい」。
スコープは docs/ideas/productization-scope-proposal.md v1.5 項目5 の承認済み範囲）。

- **タップ = 左クリック**（タップ位置へカーソル移動→クリック）
- **1本指ドラッグ = カーソル移動**（ボタンは押さない。マウスを滑らせる操作に相当）
- **2本指ドラッグ = スクロール**（ホイールイベント。ナチュラル方向=指と同方向にコンテンツが動く）
- **Apple Pencil = 筆圧なしのポインタ扱い**（指と同じ）

経路は既存TCP接続（iPad listen tcp/7789・usbmux直結）の**逆方向メッセージ**。
PC側は SendInput で仮想DP（VDD出力）の座標へマップして注入する。

## 受け入れ条件（correctness）

- [ ] iPad画面をタップすると、PCでその位置に対応するクリックが発生する（K実機目視）
- [ ] 1本指ドラッグでPCカーソルが追従して動く（K実機目視。カーソル合成済みなのでiPad上で見える）
- [ ] 2本指ドラッグでスクロールが発生し、方向がナチュラル（指と同方向にコンテンツ移動）（K実機目視）
- [ ] 座標が正しい: iPad画面の四隅近くをタップ→PC側カーソルが仮想DPの対応する四隅近くへ移動（K目視＋PC側ログの座標で機械確認）
- [ ] タッチメッセージのエンコード/デコードがラウンドトリップ一致（Swift単体テスト・Windows swiftcで実行）
- [ ] PC側ローカル機械検証: モック（Pythonスクリプト）がタッチメッセージを送信→GetCursorPos が期待座標±2px に移動・クリック/ホイールの注入カウントがログと一致（iPad実機なしで判定）
- [ ] 映像配信の既存受入が壊れていない: 逆方向トラフィック追加後も欠落0・fps維持（E2E 30秒の既存判定枠）
- [ ] 常駐が壊れていない: verify-replug 短サイクル(3回)PASS（継続時間判定込み）

## 制約

- ワイヤフォーマットは既存 [u32 length][u8 type][payload] を踏襲し、**新type=8(touch)を追加**（既存type 1〜7と衝突しない）
- 旧バージョンのPC側デーモンが新iPadアプリと繋がっても壊れない（未知typeは無視される既存挙動を維持）
- カーソル移動イベントはiPad側で最小間隔≈8msにレート制限（マウス振り回しでリンクを飽和させない）
- SendInput はデーモンの対話セッション内で実行（既存のモード変更と同じ前提。サービス化しない）
- 統計オーバーレイの3本指タップトグルと共存する（3本指は今回のジェスチャに割り当てない）

## 非スコープ

- 長押し→右クリック・ドラッグ&ドロップ（左ボタン押下ドラッグ）・ピンチズーム
- Apple Pencil の筆圧・傾き（Windows Ink連携）
- 修飾キー・キーボード入力
- スクロール方向などの設定ファイル化（v1.5後続のconfigタスクで）
- タッチのビジュアルフィードバック（iPad側の波紋等）
